# Аптечный бот — неликвид и сроки годности

Telegram-бот для аптечной сети. Заведующие и менеджер по ассортименту присылают выгрузку из учётной
системы — или бот сам берёт свежий файл с Яндекс Диска — и получают сводку в чате, отчёт в Excel и
обновлённую Google-таблицу:

- **Неликвид** — товары без продаж 90+ дней (или ни разу не продававшиеся) дороже 3000 ₽ по аптеке:
  деньги, замороженные на полке;
- **Сроки годности** — серии, у которых срок истекает в ближайшие 30 дней или уже истёк (просроченное
  подсвечено);
- **Приоритет** — пересечение двух отчётов: серия не продаётся и скоро истечёт — первые кандидаты на
  возврат поставщику или перемещение в другую аптеку.

Каждое утро бот сам строит оба отчёта по свежим файлам с Яндекс Диска и публикует их в рабочем чате.

**Стек:** Python 3.12 · python-telegram-bot 22 (JobQueue) · pandas · openpyxl · gspread · aiohttp ·
pydantic-settings · pytest + pytest-asyncio · ruff · mypy (strict) · systemd · GitHub Actions
(тесты + деплой по SSH) · uv.

## Референс и что из него взято

Проект — переделка [Anniegard/bot-mont-shk](https://github.com/Anniegard/bot-mont-shk): складского
Telegram-бота, который обрабатывает Excel-выгрузки («Без движения» и «24 часа» — прогноз списаний),
пересекает их по ID тары и пишет результат в Google Sheets. Технология и схема работы сохранены,
предметная область — аптечная сеть: товар без движения → неликвид, прогноз списаний → сроки годности,
ID тары → серия препарата.

| Приём референса | Как реализован здесь |
|---|---|
| Две выгрузки → два отчёта и их пересечение: «Без движения» × «24 часа» по ID тары | «Неликвид» × «Сроки годности» по аптеке, товару и серии → лист «Приоритет» |
| Группировка: идентификаторы через `\n` в одной ячейке, порог `Стоимость > 2000` | Серии одного товара аптеки — в одной ячейке, порог `ILLIQUID_MIN_SUM` (3000 ₽) |
| Snapshot последней выгрузки: второй отчёт считается без повторной загрузки первой | Снимки в JSON с атомарной записью; их свежесть — в Google-таблице и в `/status` |
| Один лист Google Sheets: левый блок с B2, правый с K2 | Слева «Неликвид» (B2:H), справа «Сроки годности» (K2:Q), свежесть — S2:T3, отдельный лист «Приоритет» |
| Постоянные кнопки, документ до 20 МБ, zip с Excel внутри | «📦 Неликвид», «⏳ Сроки годности», «☁️ Взять с Я.Диска», «❓ Помощь»; те же лимиты |
| Я.Диск по OAuth: последний файл папки, проверка ссылки на скачивание (HTTPS + домены Яндекса), потоковое скачивание с лимитом | `yadisk.py` на aiohttp с теми же проверками |
| Блокировка: пока идёт обработка, второй файл получает отказ | `asyncio.Lock` + `BusyError` |
| Администраторы по списку ID, лог с ротацией 5 МБ × 3, systemd-юнит, деплой по SSH из GitHub Actions | `ADMIN_USER_IDS` и `/status`, `logging_setup.py`, `deploy/pharmacy-stock-bot.service`, job `deploy` в `ci.yml` |

## Что сделано иначе и почему

Референс — 8,6 тыс. строк в `bot/` (только `handlers.py` — 1065 строк, `db.py` — 1425) с ИИ-ассистентом,
сырой БД, синхронизацией кейсов и сценарием «Задержка склада». Здесь взят основной сценарий — две
выгрузки, их пересечение, Google Sheets, Яндекс Диск, расписание — и собран так, чтобы его можно было
прочитать и проверить целиком: около 1,5 тыс. строк кода и 0,8 тыс. строк тестов.

1. **Нераспознанные даты не пропадают молча.** Референс разбирает даты через
   `pd.to_datetime(…, errors="coerce")`: значение, которое не удалось разобрать, становится пустым без
   предупреждения. В аптечном отчёте это опасно — пустая дата продажи означает «ни разу не продавался», а
   серия без срока годности выпадает из отчёта. Здесь разбор останавливается с примерами значений:
   «Не разобрал даты в столбце «срок годности»: «31.02.2026» — нужен формат дд.мм.гггг». В одном столбце
   могут встречаться и ячейки-даты Excel, и текст — они разбираются поштучно.
2. **Один `except Exception` вместо 27.** В референсе 27 перехватов `except Exception`. Здесь он один — на
   границе с Google Sheets, где сбой API не должен терять уже готовый Excel-отчёт
   (тест `test_sheet_failure_keeps_the_report`). Остальные ошибки типизированы (`TableError`,
   `ServiceError`, `YandexDiskError`, `BusyError`) и превращаются в сообщения, понятные сотруднику аптеки.
3. **Полный набор правил линтера.** Ruff в референсе проверяет только `F` и `E9` (в конфиге — «expand
   locally when ready»). Здесь включены E, F, W, I, B, UP, S (bandit), C4, SIM, PT, RUF, ASYNC и mypy в
   строгом режиме. Правило ASYNC240 нашло синхронный `Path.unlink` в async-функции — удаление
   недокачанного файла вынесено в `asyncio.to_thread`.
4. **Одна логика для кнопок, расписания и командной строки.** `ReportService` не знает о Telegram: его
   вызывают обработчики кнопок, ежедневная задача JobQueue и `report_cli` (отчёты без бота — для проверки
   на своих выгрузках). Правила отчётов в `reports/` — чистые функции над DataFrame.
5. **Токены не попадают куда не надо.** Токен бота входит в URL запросов к Bot API, а httpx пишет эти URL
   в лог на уровне INFO — логгер httpx приглушён. OAuth-токен Яндекса уходит только в API: файл по
   выданной ссылке скачивается отдельной сессией без заголовка `Authorization` (это проверяет тест).
6. **Клиент Яндекс Диска проверяется по-настоящему.** Тесты поднимают локальный эмулятор трёх ручек API на
   `aiohttp.web`: настоящий HTTP и потоковый приём файла кусками по 256 КБ, статусы 401/403/404/503,
   подменённая ссылка на чужой домен, «лживый» размер в метаданных, удаление недокачанного файла.
   Первая версия тестов была на aioresponses, но версия 0.7.9 несовместима с aiohttp 3.14
   (`ClientResponse.__init__() missing … 'stream_writer'`). Вместо того чтобы закреплять старый aiohttp,
   тесты переведены на эмулятор.

## Как работает

- Команды `/start`, `/help` и `/status` — для администраторов: свежесть данных, занят ли бот, подключены
  ли Яндекс Диск и Google-таблица.
- Файл — `.xlsx`, `.xls` или zip с таблицей внутри, до 20 МБ (больше Bot API скачать не даёт); файлы
  крупнее — через Яндекс Диск (`YANDEX_MAX_MB`, по умолчанию 100 МБ). Если отчёт не выбран кнопкой, тип
  выгрузки определяется по столбцам. Названия столбцов разных систем сводятся к одному виду:
  «Наименование» и «Номенклатура» — это «Товар», «Годен до» — «Срок годности».
- Бот отвечает только сотрудникам из `ALLOWED_USER_IDS`; незнакомому пользователю он показывает его ID,
  чтобы тот передал его администратору.
- Одна обработка за раз: второй файл во время первой получает понятный отказ, а не гонку за снимки.
- После каждой выгрузки сохраняется снимок её результата, поэтому «Приоритет» пересчитывается, когда
  приходит вторая выгрузка, без повторной загрузки первой.
- В ответ приходят HTML-сводка, отчёт Excel из трёх листов («Неликвид», «Сроки годности» с подсветкой
  просроченного, «Приоритет») и ссылка на Google-таблицу. Если Google недоступен, отчёт всё равно
  приходит, а в чат — причина.
- Ежедневная задача в `DAILY_REPORT_TIME` (часовой пояс `TIMEZONE`) берёт последние файлы из папок
  Яндекс Диска и публикует сводки и отчёты в `REPORT_CHAT_ID`; проблемы с источником тоже приходят в чат.

## Быстрый старт

Отчёты без Telegram — на демо-выгрузках пяти аптек из `examples/`:

```bash
uv sync --group dev
uv run python -m pharmacy_bot.report_cli --stock examples/остатки.xlsx \
    --expiry "examples/сроки годности.xlsx" --today 2026-09-11
```

```text
Неликвид по файлу «остатки.xlsx»
Без продаж 90+ дней: 22 позиции на 214 954 ₽ в 4 аптеках.
Больше всего: Аптека №5, ул. Гагарина, 21 — 104 326 ₽; Аптека №3, ул. Садовая, 7 — 53 761 ₽; Аптека №1, ул. Ленина, 10 — 29 081 ₽.

Приоритет посчитается, когда будут обе выгрузки — остатки и сроки годности.

Сроки годности по файлу «сроки годности.xlsx»
⚠️ Просрочено: 5 серий на 14 697 ₽ — снять с продажи.
Истекает в ближайшие 30 дней: 7 серий на 49 238 ₽.

Приоритет: 6 серий без продаж с истекающим сроком на 39 509 ₽ — вернуть поставщику или переместить.
```

Отчёт Excel появляется в `output/reports/`. Демо-выгрузки пересоздаются командой
`uv run python -m pharmacy_bot.demo examples`: генератор детерминированный, цифры выше воспроизводятся.
Названия столбцов в двух файлах намеренно разные — как у выгрузок из разных отчётов учётной системы.

Бот:

```bash
cp .env.example .env    # обязательно: TELEGRAM_TOKEN и ALLOWED_USER_IDS
uv run python -m pharmacy_bot
```

## Настройки (.env)

| Переменная | Назначение | По умолчанию |
|---|---|---|
| `TELEGRAM_TOKEN` | токен бота от BotFather | — |
| `ALLOWED_USER_IDS`, `ADMIN_USER_IDS` | ID сотрудников и администраторов через запятую | пусто |
| `SPREADSHEET_ID`, `GOOGLE_CREDENTIALS_PATH` | Google-таблица и ключ сервисного аккаунта; без ID выгрузка в таблицу выключена | —, `credentials.json` |
| `WORKSHEET_NAME`, `PRIORITY_WORKSHEET_NAME` | листы для двух блоков и для «Приоритета» | `Отчёт аптек`, `Приоритет` |
| `YANDEX_OAUTH_TOKEN` | OAuth-токен Яндекс Диска; без него кнопка «Взять с Я.Диска» выключена | — |
| `YANDEX_STOCK_DIR`, `YANDEX_EXPIRY_DIR` | папки с выгрузками | `disk:/Отчёты аптек/остатки/`, `…/сроки/` |
| `YANDEX_MAX_MB` | предел размера файла с Диска | 100 |
| `ILLIQUID_DAYS`, `ILLIQUID_MIN_SUM`, `EXPIRY_DAYS` | правила отчётов | 90, 3000, 30 |
| `DAILY_REPORT_TIME`, `REPORT_CHAT_ID`, `TIMEZONE` | ежедневный отчёт; без времени и чата выключен | —, —, `Europe/Moscow` |
| `DATA_DIR` | снимки, отчёты, временные файлы | `data` |

Лог — `logs/bot.log` с ротацией 5 МБ × 3 и дублем в консоль.

## Google-таблица

На листе `WORKSHEET_NAME` левый блок «Неликвид» начинается с B2, правый «Сроки годности» — с K2: в строке 2
заголовок блока, в строке 3 названия столбцов, данные с 5-й. В S2:T3 — когда и из какого файла получен
каждый снимок. Перед записью очищаются только эти диапазоны (`B2:H`, `K2:Q`, `S2:T3`), так что остальное
оформление листа сохраняется. Лист `PRIORITY_WORKSHEET_NAME` перезаписывается целиком. Числа уходят
числами, даты — строками «дд.мм.гггг».

## Развёртывание

VM с systemd: `deploy/pharmacy-stock-bot.service` запускает бота от отдельного пользователя с
`ProtectSystem=strict` — писать можно только в `data/` и `logs/`. Workflow `.github/workflows/ci.yml`
на каждый push гоняет ruff, mypy и pytest, а на `main` после зелёных тестов выкладывает версию по SSH
(`appleboy/ssh-action`): `git reset --hard <sha>`, `uv sync --frozen --no-dev` по `uv.lock`, перезапуск
сервиса и проверка, что он поднялся. Секреты `VM_HOST`, `VM_USER`, `VM_SSH_KEY` — в environment
`production`.

## Структура

```text
src/pharmacy_bot/
├── reports/
│   ├── loader.py      # zip → Excel, синонимы столбцов, типы, понятные ошибки
│   ├── rules.py       # неликвид, сроки годности, приоритет
│   └── models.py      # строки отчётов
├── service.py         # файл → правила → снимок → Excel → Google Sheets → сводка
├── storage.py         # снимки последних выгрузок (JSON, атомарная запись)
├── excel_export.py    # отчёт из трёх листов
├── sheets.py          # блоки в Google Sheets (gspread)
├── yadisk.py          # REST API Яндекс Диска на aiohttp
├── bot.py             # обработчики Telegram, доступ, ежедневная задача
├── texts.py           # тексты и склонения («1 позиция», «5 серий»)
├── config.py          # настройки из .env (pydantic-settings)
├── logging_setup.py   # лог с ротацией, без токена бота
├── report_cli.py      # отчёты без Telegram
└── demo.py            # демо-выгрузки
deploy/                # systemd-юнит
examples/              # демо-выгрузки пяти аптек
```

## Как проверялось

Windows 10, Python 3.12 (uv):

- `ruff check`, `ruff format --check`, `mypy` (strict, 17 файлов) — без ошибок;
- `pytest` — 51 тест: клиент Яндекс Диска против эмулятора (15), разбор выгрузок и правила (12), снимки и
  Google Sheets (11), сервис (7), обработчики Telegram (6);
- демо через `report_cli` — цифры выше; листы Excel-отчёта: 22, 12 и 6 строк.

Не проверялось вживую: Telegram Bot API (обработчики вызываются с подменёнными `Update` и `Context`, а
`build_application` проверен на регистрацию обработчиков и ежедневной задачи), Google Sheets (экспорт
проверен на поддельном листе — диапазоны и значения), настоящий Яндекс Диск (эмулятор повторяет только три
ручки API), GitHub Actions и деплой по SSH.
